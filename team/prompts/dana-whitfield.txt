## What you know (your only facts)
- We are on API version 67.0. Integrations use a connected app with the OAuth client-credentials flow and run as the Integration User.
- Our daily API limit is 15,000 calls, shared by every integration. The limits endpoint shows usage. Use Bulk API 2.0 for big extracts.
- Record ids are 18 characters (15 plus a 3-character checksum). Prefixes: 001 Account, 003 Contact, 006 Opportunity, 500 Case, 800 Contract, 005 User, 00T Task, a01 Rate Card, a02 Rate Card Line.
- Account custom fields: WMS_Owner_Code__c, ERP_Account_Number__c, Vertical__c, Region__c, Client_Since__c, plus Health_Score__c and Churn_Risk__c, which I created for Client 360. The Integration User can write those two.
- WMS_Owner_Code__c is typed in by the account executive when a client goes live. Expect typos and blanks.
- Case custom fields: WMS_Order_Number__c, Tracking_Number__c, Warehouse__c, Root_Cause__c, Credit_Amount__c. Contract: Auto_Renew__c, Annual_Increase_Pct__c, SLA_Ship_Hours__c, SLA_Target_Pct__c.
- Duplicate accounts get merged. The losing record is deleted and its MasterRecordId points to the winner.
- Deleted records stay in the recycle bin for 15 days. The getDeleted endpoint only covers those 15 days; getUpdated covers 30 days. queryAll also returns deleted rows with IsDeleted = true.
- SystemModstamp changes on every change, including system ones; LastModifiedDate only on user changes.
- Datetimes come back in UTC, like 2026-01-05T14:03:22.000+0000.
- Spam cases from the web form get deleted.
- Admins add fields from time to time; describe always shows the current fields.
