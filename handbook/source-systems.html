Everything except the public APIs runs on your machine. The databases listen on localhost:5432 (or the port in HL_PG_PORT) and the APIs on http://localhost:8080. Your cloud platform cannot reach any of them: nothing on the internet can connect in. Plan how data leaves your machine.

How the systems join

Nothing enforces these joins. Each one was keyed by a person or copied between systems by an integration, and each one breaks in its own way. The labels on the lines say how.

Each source section ends with its ER diagrams. Plain-text versions with every column, to attach to an AI chat or paste into a README (GitHub draws Mermaid), are in handbook/erd/: wms · ax2012 · salesforce · carrier_api · iot · edi · business_files · tracker.

  • Client: WMS owner.owner_code = Salesforce Account.WMS_Owner_Code__c; WMS owner.erp_account_nbr and Salesforce Account.ERP_Account_Number__c = AX custtable.accountnum (one row per legal entity, so filter on dataareaid).
  • Package: WMS shipment.tracking_nbr (and shipment_carton.tracking_nbr) = carrier API tracking_nbr = the text inside AX carrier-bill lines (vendinvoicetrans.name).
  • Client PO: EDI 940 W05 element 3 = WMS order_header.client_order_ref; cases mention order numbers in Case.WMS_Order_Number__c.
  • Invoice: WMS billing_record.invoice_ref = AX custinvoicejour.invoiceid.
  • Rates: Salesforce Rate_Card_Line__c (per Charge_Code__c) is the signed contract; WMS billing_rate is what a billing analyst keyed from it.
  • People: WMS app_user.personnel_nbr = AX hcmworker.personnelnumber.
  • Places: IoT sensor.warehouse_code and zone_code = WMS warehouse.warehouse_code and zone.zone_code.

WMS (warehouse management)

Harborline’s legacy on-prem WMS runs every warehouse: receiving, put-away, inventory, picking, packing, shipping, returns, cycle counts and the daily billing accruals. Its layout follows the common WMS design (owners, materials, locations, license plates, tasks). Owner: Marcus Bell, WMS Application Administrator.

Host
localhost, port 5432 (or HL_PG_PORT)
Database / schema
wms / wms
Login
etl_reader, password HL_ETL_PASSWORD in .env (default etl-reader-2026). The other read-only login you may see in the database’s activity, uat_reviewer, is Iris Novak’s for dashboard reviews.
Change capture
Logical replication; publication hl_wms_cdc covers every table in the schema

Behaviour reference

  • Time. Every timestamp is local warehouse time stored without a time zone. The site’s IANA zone is in warehouse.time_zone. During the autumn daylight-saving change the 01:00–02:00 hour occurs twice.
  • Units. US sites record pounds and inches; TOR1 and MTY1 record kilograms and centimetres. The unit is stored on the row (weight_uom, dim_uom).
  • Audit columns. create_ts, mod_ts, create_user, mod_user are maintained by the application, not by triggers. order_line has no audit columns.
  • Deletes are physical. Cancelled order lines, zero-quantity inventory rows, voided cartons, ASNs cancelled before arrival, billing records corrected before invoicing and items created in error are removed from the table.
  • Nightly housekeeping. At 02:00 local time per site: storage accrual, deletion of tasks older than 180 days, cleanup of zero-quantity inventory.
  • Ledger. inventory_txn is immutable; corrections are reversing rows.
  • Rates. billing_rate is overwritten in place when a rate changes. No history is kept.
  • Labels. Re-printing a label gives the shipment a new tracking_nbr.
  • Releases. Schema changes ship with application releases recorded in sys_release.
  • Identifiers. Orders HL + 10 digits, shipments SH + 9, receipts RC + 8, ASNs ASN-<owner>- + 6, returns RMA + 8, license plates LP + 10.
  • Statuses. Orders move NEW → ALLOCATED → RELEASED → PICKING → PACKED → SHIPPED, with ON_HOLD, BACKORDERED and CANCELLED on the side.
  • Personal data. order_header.ship_to_* holds consumer names, addresses, phones and emails.

Conventions

  • recid is the surrogate key every relation points to; recversion and partition (5637144576) are system columns. The database has no foreign keys.
  • Company tables carry dataareaid; shared tables (party, address, main account, general journal, currency, exchange rate, worker) do not. A client served from US and Canadian sites has a custtable row in each entity with the same account number.
  • custtable has no name column. The name is on dirpartytable, through custtable.party.
  • createddatetime and modifieddatetime are UTC.
  • An empty date is 1900-01-01; an open-ended validto is 2154-12-31 23:59:59. Addresses, person names and exchange rates are date-effective: an edit closes the current row and inserts a new one.
  • Exchange rates are stored per 100 units: 135.2 means 1 EUR = 1.352 USD.
  • Posted invoices never change; credit notes are negative invoices. Settling a payment updates the invoice’s custtrans row (settleamountcur, closed, lastsettledate); a reversed settlement is deleted from custsettlement. Lines of unposted journals (ledgerjournaltrans) are edited and deleted freely.
  • In generaljournalaccountentry credits are negative. Ledger dimensions display as MainAccount-Site-Department, for example 4010-ATL1-OPS.
  • Identifiers: customers C + 5 digits, vendors V + 5, invoices US-INV0012345, vouchers US-V12345678.

Behaviour reference

  • Ids are 18 characters: 15 plus a 3-character case checksum. Prefixes: 001 Account, 003 Contact, 006 Opportunity, 500 Case, 800 Contract, 005 User, 00T Task, a01 Rate Card, a02 Rate Card Line.
  • Datetimes come back in UTC: 2026-01-05T14:03:22.000+0000. Dates are YYYY-MM-DD.
  • SystemModstamp changes on every change, including system changes; LastModifiedDate only on user changes.
  • Merges: the losing record is deleted and its MasterRecordId points to the survivor.
  • Errors have the shape [{"message": "...", "errorCode": "..."}]: 401 INVALID_SESSION_ID, 400 MALFORMED_QUERY or INVALID_FIELD, 403 REQUEST_LIMIT_EXCEEDED, 404 NOT_FOUND.
  • SOQL supported here: a field list (with COUNT() and one-level parent fields such as Account.Name), WHERE with = != < <= > >= LIKE IN NOT IN AND OR and parentheses, date literals, LAST_N_DAYS:n, YESTERDAY, TODAY, then ORDER BY, LIMIT, OFFSET.

Carrier tracking API

An aggregator service collects tracking events from every carrier Harborline uses and serves them through one API. Owner: Tomás Ortega holds the account and key; Beth Kowalczyk owns the carriers.

Base URL
http://localhost:8080/carrier/v1
Auth
Header X-API-Key, value CARRIER_API_KEY in .env
Events feed
GET /tracking-events?since=<ISO>&cursor=<opaque>&limit=<≤500> returns {events, next_cursor, has_more}, ordered by received time
One package
GET /shipments/{tracking_nbr}
Limits
120 requests a minute, then 429 with Retry-After; about 1% of calls return 503
Retention
90 days. Older history: landing/files/carrier/history_export/*.csv.gz
  • Event codes: LABEL_CREATED, PICKED_UP, IN_TRANSIT, OUT_FOR_DELIVERY, DELIVERED, EXCEPTION, RETURN_TO_SENDER. Exceptions carry a reason: WEATHER, ADDRESS, DAMAGED, REFUSED, CARRIER_DELAY.
  • Each event has the time it happened (UTC, plus the local time with its offset as the carrier sent it) and the time the aggregator received it. An event can arrive hours after it happened, more than once, or out of order. Carriers also send corrections.
  • Tracking-number formats: UPS 1Z + 16, FedEx 12 digits, USPS 22 digits starting 9400 or 9205, DHL eCommerce GM + 16 digits, Velocity VR + 12 digits, Canada Post 16 digits, Purolator 12 digits, Estafeta 22 characters, LTL PRO numbers 9–11 digits.

IoT sensor gateway

Gateways in each warehouse push temperature and humidity readings and dock-door open and close events. Owner: Grace Liu, Facilities & Controls Engineer. Quality (Dr. Ayesha Khan) owns what the readings mean for product.

Database / schema
iot / telemetry
Tables
sensor, sensor_reading, dock_door_event
Change capture
Publication hl_iot_cdc
  • Readings are append-only, nominally every 5 minutes per sensor.
  • device_ts_ms is the device clock in epoch milliseconds (UTC) and can drift. ingested_at is when the gateway stored the row. Gateways buffer during network drops and flush late, so ingested_at can be hours after the reading. Duplicate sends happen.
  • Limits by zone type: cooler 2–8 °C, freezer −25 to −18 °C, ambient 10–32 °C, humidity under 70% RH. A cooler or freezer is in excursion after 30 minutes out of range, ambient after 240.
  • Each sensor has a calibration_due date.

EDI (X12 004010)

B2B clients, mostly auto parts and general merchandise, exchange X12 documents with Harborline through the EDI translator. Owner: Tomás Ortega. Files appear in landing/edi.

SetDirectionMeaningBecomes
940InWarehouse shipping orderA WMS order (W05 element 3, the client PO, is client_order_ref)
856InShip notice (ASN)A WMS ASN with source = EDI856
945OutWarehouse shipping adviceSent after an EDI order ships
997OutFunctional acknowledgmentSent for every inbound functional group
  • Envelope: ISA (fixed width) / GS / ST…SE / GE / IEA. SE01 counts the segments from ST to SE; GE01 counts transaction sets; IEA01 counts groups. GS01 is OW (940), SW (945), SH (856) or FA (997).
  • Segments end with ~, elements are separated by *.
  • Partners resend files, sometimes with the same control numbers and sometimes with new ones. A file can arrive with a wrong segment count.
  • A 997 reports whether the envelope and syntax were accepted. It does not prove an order was created.
  • Folders: landing/edi/<inbound|outbound>/<set>/<CLIENT>/, one file per interchange, named <set>_<CLIENT>_<yyyyMMddHHmmss>_<ISA13>.edi. Partners transmit in batches through the day.
  • The translator archives traffic older than a week: history from the initial build lives in landing/edi/archive/<inbound|outbound>/<set>/<CLIENT>/<set>_<CLIENT>_<yyyyMM>.zip, one zip per partner per month, with the original files inside. New traffic from batches and streams always arrives as loose files.

AX 2012

Database ax2012, schema dbo, 30 tables, 486 columns. Generated from simulator/harborline/schema/ax2012.sql.

Replica of the AX table layout that Harborline Finance runs on-prem. Conventions copied from AX:

  • every table has RECID (bigint surrogate key, target of every relation), RECVERSION, PARTITION
  • company-specific tables carry DATAAREAID ('us01', 'ca01', 'mx01'); shared tables do not
  • CREATEDDATETIME / MODIFIEDDATETIME are UTC (stored without time zone)
  • enums are stored as integers (lookup: srsanalysisenums); NoYes: 0 = No, 1 = Yes
  • an "empty" date is 1900-01-01; an open-ended VALIDTO is 2154-12-31 23:59:59
  • there are NO foreign keys in the database - relations exist only in the application

Table and column names are lower case here (AX uses upper case on SQL Server).
