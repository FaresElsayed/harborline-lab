One setup file gets your machine ready, on Windows or Mac. After that come the parts that are yours: trying each source system, choosing a cloud platform and opening your first pull request. Your ticks are saved.

Run the setup file

One file installs and connects everything. It skips whatever is already there, fixes the problems it knows about, and stops only when it needs you. You can run it again at any time: it carries on where it stopped. It also checks for a new version each time and asks before updating. Your data, settings and progress are kept, and your passwords and keys, which setup makes just for your install, never change.

Windows

  1. Right-click the zip and choose Extract All.
  2. In the extracted folder, double-click SETUP-WINDOWS.cmd.
  3. If Windows says it protected your PC, press More info, then Run anyway. If it says Smart App Control blocked it, see Known issues.

Mac

  1. Double-click the zip to extract it, somewhere outside iCloud such as your home folder.
  2. Open Terminal, type bash with a space after it, drag SETUP-MAC.command into the window and press Return. This avoids the security warning a double-click gets.

What it does. It checks the computer, then installs anything missing: Docker Desktop (and WSL2 on Windows), Git, the GitHub CLI, VS Code with its extensions, uv with Python 3.12, pre-commit and DBeaver. It then copies the simulator to C:\dev\harborline-lab (Mac: ~/dev/harborline-lab), starts it, and begins building the data. It creates your repository at C:\dev\harborline-analytics (Mac: ~/dev/harborline-analytics) and on GitHub, protects main, adds one DBeaver connection per source system and sets your Tracker start date. Last, it walks you through one saved chat per colleague on the AI site you choose (ChatGPT, Claude, Gemini or another), and leaves harborline-chat.zip in your dev folder. Always send that zip with a colleague’s prompt, in the same first message, or they can’t see the company and will guess.

What it needs from you. Only what a program can’t do:

  • Your name and email, for your commits.
  • Clicking Yes when Windows asks for permission (Mac: your password).
  • Accepting Docker Desktop’s agreement the first time it opens.
  • Signing in to GitHub in your browser, with the one-time code it shows you.
  • The Monday you start. Press Enter to accept the suggested one.
  • Picking your AI site, signing in, and turning off any memory that works across chats.
  • For each colleague: dragging in the zip, pasting, sending, then copying the chat’s address back. A script can’t create those chats for you. It takes about a minute each, and you can stop and carry on later.
  • A restart, if Windows needs one for WSL2. Setup starts again by itself afterwards.

Afterwards, close any terminal or VS Code window you already had open and open a new one. A terminal only sees programs that were installed before it opened, so an old window says not recognized or command not found. Setup deals with this for its own window, sometimes by carrying on in a fresh one.

How to verify

It finishes with ALL DONE, a list of your folders and links, and opens the start page. You can close the window while the data build runs: it keeps going, and the Control Center shows its progress.

If it stops

  1. It shows the exact error and puts a report on your clipboard.
  2. Paste that into your chat with Kevin O’Hara, IT help. Before your team is set up, any AI chat will do.
  3. Do what he says, then run the setup file again. Finished steps are skipped.

Every error we know of, for every step, is in Known issues, with what to do. The report and a full log are in %LOCALAPPDATA%\HarborlineLab (Mac: ~/Library/Logs/HarborlineLab).

Tried this before under another name?

Folders and repositories named harborline-simulator, harborline-3pl-simulator or harborline-data-platform are from an earlier attempt. Don’t use them. The setup file doesn’t touch them, apart from stopping the old containers so their ports are free. Their data stays on disk until you delete it, and the last screen says how.

A SQL editor runs against one database, and a query can’t reach another database. Right-click Harborline WMS and choose SQL Editor, New SQL script (Ctrl + ]). The editor’s toolbar shows what it runs against: a Harborline connection, never DBeaver Sample Database. Paste the first query and run it with Ctrl + Enter. Then do the same on Harborline AX 2012 for the second.

SELECT w.warehouse_code, w.time_zone, count(*) AS orders, max(o.received_ts) AS latest_local
FROM wms.order_header o
JOIN wms.warehouse w USING (warehouse_id)
GROUP BY 1, 2
ORDER BY 1;
SELECT c.dataareaid, c.accountnum, p.name, c.currency, c.paymtermid
FROM dbo.custtable c
JOIN dbo.dirpartytable p ON p.recid = c.party
ORDER BY 2, 1
LIMIT 20;

How to verify

Both queries return rows; the first lists every warehouse in your preset with its time zone.

Common problems
FATAL: password authentication failed for user "etl_reader"
You changed HL_ETL_PASSWORD after the first start. The password is set once, when the database volume is created; use the original value or run reset.bat.
Connection refused
The simulator is not running, or another Postgres owns the port. See Troubleshooting.
permission denied for database sim_internal
Expected. Salesforce and carrier data come only through their APIs.
[SQLITE_ERROR] … no such table: wms.order_header
The editor is on DBeaver Sample Database, which DBeaver creates on first launch. Open a new script from the wms database as above, or pick your Harborline connection in the toolbar’s connection box (Ctrl + 9). You can delete the sample database.
relation "dbo.custtable" does not exist
You ran the AX query in an editor on wms. Open a script from ax2012, or switch the toolbar’s database box (Ctrl + 0) to ax2012.

Get a token with the client-credentials flow, then run a SOQL query. Invoke-RestMethod sends a hashtable body as a form, which is what the token endpoint expects. Setup made your client id and secret just for this install: copy them from Connections in the Control Center.

$token = Invoke-RestMethod -Method Post -Uri "http://localhost:8080/sfdc/services/oauth2/token" -Body @{
  grant_type    = "client_credentials"
  client_id     = "PASTE-YOUR-SF_CLIENT_ID"
  client_secret = "PASTE-YOUR-SF_CLIENT_SECRET"
}
$headers = @{ Authorization = "Bearer $($token.access_token)" }
$soql = "SELECT Id, Name, WMS_Owner_Code__c, ERP_Account_Number__c FROM Account WHERE Type = 'Customer - Direct' LIMIT 5"
$result = Invoke-RestMethod -Headers $headers -Uri "$($token.instance_url)/services/data/v67.0/query?q=$([uri]::EscapeDataString($soql))"
$result.totalSize
$result.records | Format-Table Id, Name, WMS_Owner_Code__c, ERP_Account_Number__c

Check what that cost you against the daily limit:

(Invoke-RestMethod -Headers $headers -Uri "$($token.instance_url)/services/data/v67.0/limits").DailyApiRequests

How to verify

You see five accounts with 18-character ids starting 001, and DailyApiRequests shows Max 15000 and the remaining calls.

Common problems
401 INVALID_SESSION_ID
The token expired or the header is missing Bearer. Request a new token.
400 MALFORMED_QUERY
The SOQL was not URL-encoded, or uses syntax outside the supported subset (see Source systems).

Setup made your API key just for this install: copy it from Connections in the Control Center.

$carrier = @{ "X-API-Key" = "PASTE-YOUR-CARRIER_API_KEY" }
$since = (Get-Date).ToUniversalTime().AddDays(-3).ToString("yyyy-MM-ddTHH:mm:ssZ")
$page = Invoke-RestMethod -Headers $carrier -Uri "http://localhost:8080/carrier/v1/tracking-events?since=$since&limit=5"
$page.events | Format-Table
$page.has_more; $page.next_cursor

Events become visible as the simulated clock passes them, so a since of a few days back returns data right after a build. Follow next_cursor to page.

How to verify

Five events with tracking numbers in carrier formats (UPS 1Z…, FedEx 12 digits and so on) and a non-empty next_cursor.

Common problems
401 or 403
The X-API-Key header is missing or wrong.
429 Too Many Requests
More than 120 calls a minute. Wait the number of seconds in Retry-After.
503 Service Unavailable
Happens about once in a hundred calls on purpose. Retry with backoff.

Doing it by hand

You don’t need this if the setup file finished. It is the same work written out step by step for Windows, with the errors people usually hit: useful if you want to know what the setup file did, or if IT help sends you to one step.

Check the machine

The simulator runs entirely in Docker. Docker on Windows runs Linux containers inside WSL2, a lightweight virtual machine, so the CPU’s virtualization support must be on.

You need Windows 11, or Windows 10 version 22H2 (build 19045) or later. Home, Pro and Enterprise all work.

Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, BuildNumber

How to verify

BuildNumber is 19045 or higher (Windows 10) or 22000 or higher (Windows 11). Older? Run Windows Update until the feature update installs.

Recommended: 16 GB of RAM or more, 4 or more CPU cores, and free space on an SSD: about 12 GB for Medium, 30 GB for Large (the database, Docker images and room for replication logs). With 8 GB of RAM, use the Medium preset later.

$cs = Get-CimInstance Win32_ComputerSystem
"{0:N1} GB RAM, {1} logical processors" -f ($cs.TotalPhysicalMemory / 1GB), $cs.NumberOfLogicalProcessors
Get-PSDrive C | Select-Object @{n='FreeGB';e={[math]::Round($_.Free / 1GB, 1)}}

How to verify

RAM is 15.x GB or more and C: has 40 GB or more free. If C: is short, you can move Docker’s disk to another drive later (Docker step).

Open Task Manager (Ctrl + Shift + Esc), go to Performance then CPU, and read Virtualization under the graph. Or ask PowerShell:

(Get-CimInstance Win32_ComputerSystem).HypervisorPresent
(Get-CimInstance Win32_Processor).VirtualizationFirmwareEnabled

Either line printing True is good (the second one reads False once a hypervisor is already running, which is fine). If Task Manager says Disabled, turn it on in the firmware:

  1. Settings, System, Recovery, Advanced startup, Restart now.
  2. Troubleshoot, Advanced options, UEFI Firmware Settings, Restart.
  3. Find Intel Virtualization Technology (VT-x) or SVM Mode (AMD), usually under Advanced, CPU Configuration or Security. Enable it, save and exit (often F10).

How to verify

Task Manager shows Virtualization: Enabled.

Common problems
No virtualization option in the firmware
Some vendors hide it under “Security” or name it “Intel VT”. On a company laptop it may be locked; ask IT.
The option is greyed out
A firmware (BIOS) password or policy is set. Ask whoever manages the machine.

WSL2

One command enables the Windows features, installs the WSL2 kernel and adds Ubuntu.

wsl --install

Restart Windows when it asks. After the restart an Ubuntu window opens and asks for a new UNIX user name and password. These are only for Linux; they do not have to match your Windows account. Then bring WSL up to date:

wsl --update
wsl --set-default-version 2

How to verify

wsl --status
wsl -l -v

Default Version: 2, and Ubuntu listed with VERSION 2.

Common problems
WslRegisterDistribution failed with error: 0x80370102
Virtualization is off in the firmware, or the Virtual Machine Platform feature is missing. Fix the firmware setting (previous section), then run dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart as administrator and restart.
0x8007019e
The WSL feature is not enabled. Run dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart as administrator and restart.
WSL 2 requires an update to its kernel component
Run wsl --update.
wsl --install only prints the help text
WSL is already installed. Run wsl -l -o to list distributions, then wsl --install -d Ubuntu.
The Ubuntu window closes immediately
Run wsl --shutdown, then wsl -d Ubuntu from a terminal to see the actual error.

With the WSL2 backend, Docker’s memory and CPU limits come from WSL, not from Docker Desktop’s sliders. Give it about two-thirds of your RAM: 10 GB on a 16 GB machine, 16 GB on a 32 GB machine.

@"
[wsl2]
memory=10GB
processors=6
swap=4GB
"@ | Set-Content -Path "$env:USERPROFILE\.wslconfig" -Encoding ascii
wsl --shutdown

How to verify

Get-Content "$env:USERPROFILE\.wslconfig"

Shows the three settings. You will confirm Docker sees the memory in the next section.

failed to connect to the docker API at npipe:////./pipe/docker_engine … The system cannot find the file specified (older versions: error during connect … dockerDesktopLinuxEngine)

Accept the default file (C:\Users\you\.ssh\id_ed25519) and choose a passphrase. Windows’ OpenSSH agent remembers it so you type it once per login. Start the agent service once, as administrator:

Get-Service ssh-agent | Set-Service -StartupType Automatic
Start-Service ssh-agent

Then, in a normal terminal, add the key and tell Git to use Windows’ OpenSSH (Git ships its own copy, which cannot see the Windows agent):

ssh-add "$env:USERPROFILE\.ssh\id_ed25519"
git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"

Troubleshooting

Start with the doctor: powershell -ExecutionPolicy Bypass -File .\doctor.ps1. Then find the symptom below.

Hyper-V, WSL or virtualization errors

Most WSL and Docker start-up failures trace back to the same few things. In order:

  1. Virtualization enabled in the firmware (Task Manager, Performance, CPU).
  2. Windows features on (administrator): dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart and dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart, then restart.
  3. wsl --update, then wsl --shutdown, then start Docker Desktop.
  4. Another hypervisor product (an old VirtualBox or VMware) can conflict. Update it to a version that supports Hyper-V coexistence.
Port 5432 or 8080 already in use

Find out who owns the port:

Get-NetTCPConnection -LocalPort 5432, 8080 -State Listen -ErrorAction SilentlyContinue |
  Select-Object LocalPort, OwningProcess, @{n='Process';e={(Get-Process -Id $_.OwningProcess).ProcessName}}

A local PostgreSQL install is the usual culprit (Get-Service postgresql*). Either stop that service or move Harborline: set HL_PG_PORT=5433 (or HL_APP_PORT=8081) in .env, run stop.bat then start.bat, and use the new port in DBeaver and in every URL.

A build fails or containers restart: not enough memory

Symptoms: the build stops part-way, docker compose ps shows a container restarting, or logs mention exit code 137 or Killed. Give WSL more memory in %UserProfile%\.wslconfig, run wsl --shutdown, start Docker Desktop, and check docker info --format "{{.MemTotal}}". Close browsers with many tabs during a build, or use a smaller size.

Disk full

docker system df shows what Docker uses. docker builder prune clears the build cache. A replication slot you created and stopped reading keeps write-ahead log on disk (capped at 8 GB); drop slots you no longer use. To move Docker’s data off C:, use Docker Desktop, Settings, Resources, Advanced, Disk image location.

Line endings (CRLF) break a script

Symptoms: $'\r': command not found, or Postgres fails to initialise after you edited a file under db/init. A Windows editor saved a Linux script with CRLF endings. In VS Code, click CRLF in the status bar, choose LF, save, then run reset.bat (initialisation only runs on an empty database). In your own repository, pin endings in .gitattributes.

Antivirus or a corporate proxy gets in the way
  • Image downloads fail behind a proxy: set it in Docker Desktop, Settings, Resources, Proxies, then run docker pull postgres:17 to test.
  • winget or uv downloads fail: set HTTPS_PROXY for your user, or ask IT for the proxy address.
  • Real-time antivirus scanning can make WSL and Docker very slow. On a managed laptop, ask IT about exclusions for Docker’s data folder rather than turning protection off.
  • No internet at all during a build: set HL_OFFLINE=1 in .env.
The browser cannot reach localhost:8080
Set-Location C:\dev\harborline-lab
docker compose ps
docker compose logs --tail 100 app

If the app is restarting, the logs say why. If you changed HL_APP_PORT, use that port. A VPN client can hijack localhost; disconnect it and try again.
